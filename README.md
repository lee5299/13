# 업무 정리

Windows에서 혼자 사용하는 로컬 업무 정리 프로그램을 개발하고 있습니다. **아직 완성본이 아니며, 2026-10-30 개발 중간 상태를 다른 PC로 인계한 저장소입니다.**

요청마다 날짜가 붙은 폴더와 작업기록을 만들고, 캡처·제출물·반복업무·예상 업무부담·백업을 관리합니다. 업무자료는 지정한 로컬 폴더에 저장합니다.

## 다른 컴퓨터에서 이어가기

1. 이 저장소를 내려받고 Windows에 **.NET 10 SDK**를 설치합니다. 확인한 개발 SDK는 10.0.403입니다.
2. Codex에서 이 폴더를 열고 [개발 인계](docs/개발인계.md)를 먼저 읽도록 요청합니다.
3. 아래 명령으로 백업 도구 준비, 빌드·검사·실행파일 생성을 할 수 있습니다.

```powershell
.\scripts\백업도구준비.ps1
.\build.ps1 -Publish
.\실행\업무정리.exe
```

준비 스크립트는 restic 0.19.1 Windows x64 배포본을 공식 저장소에서 받고 고정된 SHA256을 검사합니다. 앱 사용 중 인터넷 연결은 요구하지 않습니다. 백업 도구 없이도 빌드/일반 기능 검사를 할 수 있지만 실제 백업·복원 검사는 건너뜁니다.

처음 실행하면 업무 루트폴더를 지정합니다. 시험하려면 실제 업무자료와 별도인 빈 폴더를 고르세요. 실제 업무자료·백업·복구 암호·개인 PC 설정은 이 저장소에 포함하지 않았습니다.

```powershell
# 별도 시험자료로 실행
.\실행\업무정리.exe --demo
```

시험자료의 private 암호는 `시험자료-private-0000`입니다. 실제 업무자료에는 쓰지 마세요.

## 공개/private 분리와 AI 다듬기 (2026-10-31 추가, 빌드 전)

- **공개 기본내용(상단):** 요청 원문·이해·맥락을 적습니다. AI가 읽을 수 있는 영역이며 인터넷 게시를 뜻하지 않습니다.
- **private 상세(중간, 넓게):** 명령어·구조 명칭·민감 상세를 적습니다. private 암호로 만든 키로 암호화해 저장하고, 키와 암호는 어디에도 저장하지 않습니다.
- **AI 다듬기:** 상세창의 "문장 다듬기"와 "내용+구조 다듬기" 버튼을 누를 때만 요청합니다.
  1. 공개 정리 내용을 PC 안에서 검사합니다(키·주민번호·전화번호).
  2. 검출된 값을 가린 사본만, PC에 설치한 공식 Claude Code나 Codex로 보냅니다.
  3. 응답을 프로그램이 좌우로 비교해 보여줍니다.
  4. 적용을 눌러야만 반영됩니다.
- **백업:** 주 로컬 백업은 기본으로 private(암호문)을 포함합니다. "백업파일 만들기"는 누를 때만 private을 뺀 `.wobak` 파일 하나를 만들고, 클라우드 업로드는 직접 합니다.

자세한 결정과 검증 상태는 `docs/추가요구_구현결정.md`와 `docs/요구사항대응표.md`에 있습니다.

## 배포본 만들기 (셋업 파일 + zip)

```powershell
.\scripts\백업도구준비.ps1          # 배포본에 백업 도구 포함
winget install JRSoftware.InnoSetup  # 셋업 파일 생성 도구(처음 한 번)
.\build.ps1 -Package -Version 0.1.0
```

`배포\` 폴더에 두 파일이 만들어집니다.

- `업무정리_설치_0.1.0.exe`: 관리자 권한 없이 사용자 폴더에 설치합니다. 시작 메뉴에서 "업무정리"로 검색해 실행하며, 바탕화면 바로가기는 설치할 때 선택합니다. 제거해도 업무자료·백업은 지우지 않습니다.
- `업무정리_실행판_0.1.0.zip`: 설치 없이 압축만 풀어 `업무정리.exe`를 실행합니다.

첫 실행이면 루트폴더 선택 화면이 나옵니다. 마지막 루트 위치와 시험자료는 `%LOCALAPPDATA%\업무정리`에 저장됩니다. 코드 서명을 하지 않아 셋업을 처음 실행하면 SmartScreen 경고가 나올 수 있습니다. "추가 정보 → 실행"으로 넘어가면 됩니다.

## 저장소 안내

- `src/WorkOrganizer.Core`: 폴더·기록·상태·계산·반복·백업 처리
- `src/WorkOrganizer.App`: WPF 화면과 Windows 바탕화면 연결
- `tests/WorkOrganizer.Checks`: 실제 파일 및 계산 검사
- `planning/확정요구사항.md`: 승인 당시 전체 요구·제외·유보
- `design/`: 기존 디자인과 작업기록 확대 HTML
- `docs/개발인계.md`: 확인한 범위, 알려진 문제, 다음 작업
- `planning/history/`: 과거 판단/실행 상태의 보존본. 완성/채택 승인이 아님

## 현재 확인한 범위

핵심 파일·계산·실제 restic 백업/별도복원 검사 40개가 통과했습니다. 작업 상세는 현재 시험 PC의 1920×1032 최대화 창에서 기본 글자 15로 48줄을 확인했습니다. 이는 모든 화면과 전체 제품에 대한 인수 확인을 뜻하지 않습니다.

바탕화면 아래층의 표시·클릭·포커스·Explorer 재시작과 전체 요구 대응 검증이 남아 있습니다. 일반 창 복귀는 확인했습니다. 중요한 업무에 사용하기 전 인계 문서의 미완료 항목을 검토해야 합니다.
