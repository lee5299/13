# 개발 인계 · 2026-10-30

사용자가 나머지 개발을 주말에 집의 다른 컴퓨터에서 하겠다고 명시하여 개발을 중단하고 저장한 상태다. 전체 구현 완료가 아니다. 기존 요구를 임의로 초기 버전으로 축소하지 않는다.

## 먼저 읽을 자료

`planning/확정요구사항.md`가 현재 전체 기준이다. 원본 SpecFrame 상태의 승인값은 approved다. 이 승인은 사용자의 실제 개발 시작 지시에 근거하며 실제 제품 인수 성공을 뜻하지 않는다. 디자인은 `design/`의 HTML과 두 PNG를 참조한다. 큰 작업기록 영역 요청을 유지한다.

확정된 핵심 원칙:

- Windows 개인용 로컬 앱. 요청마다 `YYMMDD_작업명_요청내용` 폴더. 요청 접수/검토중/수락은 분리하며 최초 접수시각을 보존한다.
- 원문과 본인 이해를 따로 기록. `============` 구분선, 5W1H 중 어디서 제외, 주의/개선/절차·명령어/오류·조치를 보존한다. 명령어 자동실행 기능은 없다.
- 예상량은 완료에 필요한 총 일수, 기본 1일, 0.5 입력 가능. 중요도와 별개다. 진행률·착수 예정일·실사용일수 입력·목록복사는 제외한다.
- 오늘을 포함한 평일 하루 1일치, 월요일 주 시작. 검토중은 확정 부담에서 제외하며 선택 요청 하나의 수락 가정을 보여준다. 미완료는 등록 예상량 전체를 보수적으로 계산하고 완료 후 제외한다. 과거 경과일수를 다시 환급하지 않는다.
- 완료폴더로 이동/앱 완료 버튼 모두 지원. 원래 주기를 유지하고, 같은 주기 작업 영역으로 돌아오면 진행 복귀. 앱 종료 중 이동의 완료시각을 꾸미지 않는다.
- 유형은 사용자가 이름을 정하고 반복 여부는 별도 선택한다. 유사명 클릭/체크한 양식만 복사/지난 제출물 선택 복사/이름 재사용. 이전 원본 자동 수정 금지.
- 텍스트는 표시·편집, 캡처는 클릭 미리보기, 첨부 문서 내부 미리보기/자동 분석은 없다.
- 실제 업무자료는 Git과 분리한다. 백업 범위·위치·간격·보존은 설정한다. 복구 암호는 저장소/업무자료와 따로 보관한다.

## 소스와 실행 상태

기술 구성은 .NET 10 WPF(C# UI), JSON/텍스트 정본 + 재생성 가능한 SQLite 보조 색인, restic 0.19.1이다. SDK 10.0.403, Windows 10.0.26200 환경에서 빌드/실행했다. SQLite 패키지는 Microsoft.Data.Sqlite.Core 10.0.14 + SQLitePCLRaw.bundle_e_sqlite3 3.0.5로 바꿔 이전 종속성의 취약점 경고를 해소했다.

상세 기록은 왼쪽 넓은 편집기/오른쪽 업무정보 구성이다. 일반 창 39줄, 최대화 1920×1032에서 글자 15로 48줄을 관측했다. 글자 14/15/16/18/20 선택이 있다. 마지막 UI 관측 후 미저장 업무정보 보호·메타정보 충돌 차단·회차별 시기 변경·취소 요청 조회가 소스에 추가됐다. 최종 소스의 핵심 검사는 통과했지만 추가된 UI 경로는 재검증해야 한다. UI 통과를 새 소스에 소급하지 않는다.

`docs/검사결과.json`은 현재 소스의 40개 핵심 검사 결과다. 실제 restic 백업/무변경/별도복원 해시/잠김 실패/잘못된 암호/직전 복구점 보존도 포함한다. 검사 자료 자체와 백업 저장소는 업로드하지 않았다.

## 다음 작업과 알려진 경계

1. 전체 요구 ID별로 구현 위치·검사·충족/불일치/누락/미검증 대응표를 작성한다. 현재 구현 전체를 완료로 승인한 Review/Commit은 없다.
2. 바탕화면 기본 모드를 마무리한다. 구형 WorkerW 형제 방식은 이 Windows에서 실제 실패했고 Progman 자식 DefView/WorkerW 경로를 추가했다. 새 연결은 오류 없이 전환됐지만 화면 도구가 자식 창을 `window is not a usable app window`로 거부하여 아래층의 실제 클릭/포커스는 확인하지 못했다. 일반 창 복귀는 실제 확인했다. 기본 모드 지속·Explorer 재시작·다중 화면/배율을 확인한다. 요구를 임의로 항상 위 창으로 대체하지 않는다.
3. 새 요청 등록, 유사명 선택, 양식 체크, 반복 회차/이번만 시기 변경/건너뛰기, 지난 파일 복사, 캡처 Ctrl+V/끌어놓기, 제출항목 연결, 완료/되돌림, 요청일·완료일 검색/주월 묶음을 실제 UI에서 확인한다.
4. 외부 편집 충돌·미저장 닫기 보호는 핵심 로직 검사 외에도 실제 앱과 외부 편집기로 검증한다. 메타정보 변경이 탐색기/앱 동시 작업에서 손실되지 않는지 확인한다. 기록 구분선이 원문 안에 들어오는 경우의 표시 파싱도 검토한다.
5. 부분 생성 후 재시도, 이동 저널의 회복, 재연결, 중복 ID/동명 파일/잠김/권한 실패를 세부 검증한다. 저널 발견 안내만 있는 부분을 실제 자동 회복 완료로 부르지 않는다.
6. 백업 설정 저장 후 다시 열어 실행하는 현재 흐름을 실제 검증/개선한다. DPAPI 복구키 내보내기/다른 PC 가져오기, 복원 취소·현재 파일 적용, 장치 분리/용량 부족/앱 응답성·보존 정리를 확인한다. 측정하지 않은 사용자 자료의 속도를 보장하지 않는다.
7. SQLite 색인은 현재 보조 재생성 캐시이며 화면 검색은 읽은 원본 목록에서 수행한다. 색인 존재를 실제 SQL 검색 경로 검증으로 확대하지 않는다.
8. 사용자 실제 업무 한 건에 대한 목적 검증은 미수행이다. 소스와 실행파일을 같은 버전으로 맞춘 뒤 인수해야 한다.

일부 UI는 간단한 기본 WPF 스타일이며 목업과의 세부 시각 대응도 남아 있다. 제출항목 실선/캡처 점선 구분 등 전체 시각 요구를 마지막에 대조한다.

## SynFrame 상태 인계

현재 개발 run `run-686e69d3d23b4ef987790da6a7aee8cc`는 사용자 중단 요청으로 **SUSPENDED**다. DERIVE_CAPABILITY 시제품 관측 `op-d6b8f37e400349ac99941831af6cda49`는 실제 관측이 보존돼 있으나 결과 적용 전이다. 해석/도구 적용·탐색/조합·현재 Review/채택·최종 실행 의무가 남아 있다. 실제 앱 소스와 시험을 그 관측으로 재사용하고 최종 채택 완료를 소급하지 않는다.

이전 방법조사 run `run-637a8f4d78b6492b8e530596c7980057`도 SUSPENDED다. 과거 Review 초안은 “UPDATE에 미해결 학습 공백을 숨길 수 없음” 진단으로 적용되지 않았다. 학습/실제 관측을 전부 반복하지 말고 원래 범위와 현재 소비를 대조하되, 적용 안 된 Review를 승인으로 쓰지 않는다.

`planning/history/synframe-state.sqlite3`는 원래 상태의 보존본이다. 기기별 절대경로 참조는 역사로 남아 있으므로 새 PC의 경로/산출물 버전과 대조해야 한다. 해시나 과거 성공 기록을 단순 치환하지 않는다. 원래 관측/실패를 보존한 상태 복원 또는 연결된 후속 실행으로 이어간다. `planning/history/work/`에는 당시 저작·관측 파일을 함께 보관한다.

앱 접근 재승인은 성공했다. 이전 시간초과를 현재 장애로 오해하여 다시 개발을 막지 않는다. 새 PC에서는 그 PC의 앱 접근 승인을 별도로 사용할 수 있다.

앱 실행 자체에 SpecFrame/SynFrame/모델 API 키는 필요하지 않다. 개발 대화를 이어가는 Codex는 필요한 설치된 스킬 전문을 읽고 실제 저장 상태를 복원한다.
