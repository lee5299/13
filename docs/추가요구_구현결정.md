# 추가 요구 구현 결정 · 2026-10-31

`planning/추가요구사항_private_AI_백업.md`의 DEFERRED_CHANGE 항목에 대해 구현 단계에서 정한 내용이다. 요구를 낮춘 것은 없다. 아래 사항은 모두 **소스 작성 단계**이며 이 문서를 쓴 세션에서는 빌드·실행·검사를 하지 못했다(클라우드 작업환경에 .NET SDK 없음). Windows에서 `.\build.ps1 -Publish`로 확인해야 한다.

## 1. private 실제 접근 차단 수단 (AI_PRIVATE_DENY · AI_EXTERNAL_DENY)

- **선택:** 저장 시점 암호화. private 상세는 업무폴더의 `private\상세기록.private`에 AES-256-GCM 암호문으로만 저장한다. 파일 내용 자체가 암호문이며, 앱이 열 때만 암호를 묻는 방식이 아니다.
- **키 구조(2026-10-31 변경):** 실제 암호화 키(자료 키)는 무작위 32바이트다. 사용자가 입력하는 업무정리 암호에서 PBKDF2-SHA256(600,000회)으로 만든 키로 자료 키를 감싸 `.업무정리\private보관소.json`에 둔다. 암호를 바꾸면 포장만 다시 만들고 private 파일은 그대로 둔다. 옛 포장(`.previous`)은 지워 옛 암호로 열 수 없게 한다. 1판 보관소는 잠금 해제할 때 파일을 다시 쓰지 않고 2판으로 올린다.
- **사용자 암호 하나(2026-10-31 사용자 요청):** 사용자가 입력하는 암호는 업무정리 암호 하나다. private 잠금 해제, 백업 복구정보, 백업파일(.wobak)에 같은 암호를 쓰며 어디에도 저장하지 않는다.
- **자동 백업 내부 암호:** restic 저장소의 내부 암호는 앱이 무작위로 만들어 이 PC에 DPAPI로 보관한다. 1시간마다 도는 자동 백업이 사용자 입력 없이 써야 하기 때문이다. DPAPI는 같은 Windows 계정의 프로그램이면 풀 수 있으므로, 이 값은 사용자 암호와 다르게 둔다. 이 값이 새어 나가도 백업 안의 private은 사용자 암호로 감싼 키의 암호문이라 읽을 수 없다.
- **이유:** 앱이 실행하는 Codex·Claude, 사용자가 폴더를 여는 외부 AI 모두 같은 Windows 사용자 권한으로 실행된다. 이 경우 폴더 권한(ACL) 거부는 소유자가 다시 풀 수 있고, 관리형 deny_read만으로는 셸 하위 프로세스의 읽기를 막지 못한다(승인 문서의 OpenAI 근거). 디스크에 평문이 없고 키도 없으면 직접읽기·명령읽기·파생본 읽기 모두 암호문만 얻는다.
- **업무별 결합:** 암호화에 업무 ID를 추가 인증정보(AAD)로 넣어, 다른 업무의 private 문서를 바꿔 넣으면 해독이 실패한다.
- **파생본:** `.previous`·임시본·충돌 보존본도 암호문으로만 쓴다. 생성 저널에는 공개 내용만 쓴다. 검색 색인(`검색.sqlite`)에는 공개기록의 요청 원문만 넣고 `secure_delete`를 켠다. private은 로컬 검색 대상에서도 뺐다.
- **키가 메모리에 있는 동안:** Codex처럼 명령 도구가 있는 연결로 요청할 때와 외부 폴더 AI 작업 중에는 키를 0으로 지우고 잠근다. Claude 연결은 `--tools ""`로 모든 도구를 끈 텍스트 응답 전용이라 잠그지 않는다.
- **범위 밖(미검증):** 같은 사용자 권한의 프로그램이 잠금 해제 중인 앱의 메모리를 읽는 경우. .NET 문자열은 즉시 지울 수 없어 잠근 뒤에도 메모리에 남을 수 있다. 사용자·관리자가 경계 자체를 해제한 환경도 보호 성공으로 주장하지 않는다.
- **외부 편집기:** private은 메모장/Notepad++로 여는 기능을 제공하지 않는다(평문 임시본 방지). 공개기록만 외부로 연다. 기존 D03/PVT04의 외부 편집은 공개기록에 적용된다(추가 요구 우선).
- **암호 분실:** private 암호를 잃으면 private을 복구할 수 없다. 화면에서 별도 보관을 안내한다.

## 2. 외부 폴더 AI 작업 흐름 (PRIVATE_LOCK_FLOW)

설정 → "AI 연결 / 전송 전 검사" 탭에서 시작한다.

1. 상세창에 미저장 private이 있으면 저장할지 묻는다. 거절하면 시작하지 않는다.
2. private 키를 지운다.
3. 루트 안의 미분류 이전 기록 평문(`업무기록*.txt`)과 private 폴더의 암호화되지 않은 파일을 점검한다. 하나라도 있으면 시작하지 않는다.
4. 업무 루트에서 PowerShell 창을 열고, 선택하면 `claude` 또는 `codex`를 실행한다. 이때 API 키 환경변수는 지운다.
5. 잠금 상태는 `.업무정리\외부AI잠금.json`에 남는다. 앱이 비정상 종료돼도 다시 열면 잠금 배너가 보인다.
6. 끝내려면 "외부 AI 작업 종료 확인"을 누른다. 연 창이 아직 실행 중이면 종료할지 묻고, 종료를 확인한 뒤 잠금을 푼다. 그 밖의 claude/codex 프로세스 수도 안내한다.

## 3. 앱 안 AI 연결 (AI_SERVICE_CONSTRAINT)

- 사용자 요청(2026-10-31)에 따라 CLI 방식일 필요는 없고 "프로그램에서 연결"되면 된다. 다만 "API 과금 없이 본인 구독 사용"과 "앱이 토큰을 중개하지 않음" 조건을 함께 만족하는 수단은 공식 프로그램을 앱이 뒤에서 실행하는 방식뿐이라 이 방식으로 구현했다. 연결은 `IAiConnector` 인터페이스 뒤에 두어 교체할 수 있다.
- **Claude:** `claude -p --output-format text --tools "" --strict-mcp-config --disable-slash-commands --no-session-persistence`. 프롬프트는 표준입력으로 보낸다.
- **Codex:** `codex exec --sandbox read-only --skip-git-repo-check --ephemeral -C <빈 임시폴더> --output-last-message <파일> -`. 요청하는 동안 private을 잠근다.
- **작업 폴더:** 매번 새로 만든 빈 임시 폴더를 쓰고 업무 루트는 넘기지 않는다.
- **과금 전환 방지:** `ANTHROPIC_API_KEY`·`OPENAI_API_KEY`·`CODEX_API_KEY`·Bedrock/Vertex 설정 등을 자식 프로세스 환경에서 지운다.
- **실패 처리:** 로그인·한도·통신·옵션 미지원·빈 응답을 구분해 안내하고 문서는 바꾸지 않는다. 다른 연결로 자동 전환하지 않는다.
- **로그인 확인:** 설정의 "연결·로그인 상태 확인"이 `claude auth status` / `codex login status` 결과를 그대로 보여준다. 구독 로그인인지는 사용자가 확인한다.
- **미검증:** 설치된 버전이 위 옵션을 모두 지원하는지, 실제 본인 계정으로 연결·호출되는지.

## 4. 다듬기 흐름 (FLOW_AI)

- **보내는 범위:** 공개기록 중 "받은 요청 원문" 절을 뺀 나머지만 보낸다. 원문은 보내지도 바꾸지도 않는다(R06).
- **로컬 검사:** 검사는 PC 안의 정규식으로만 한다. 검출되면 값·줄·칸을 보여주고 확인/취소를 받는다. 확인하면 `[[가림-요청태그-번호]]`로 바꾼 사본만 보낸다. 같은 값은 같은 표시를 쓴다.
- **재검사:** 확인 대화상자를 닫은 뒤 내용이 바뀌었으면 다시 검사하고, 이전 확인을 새 내용에 쓰지 않는다.
- **복원:** 응답의 표시는 이 요청의 대응표로만 되돌린다. 표시가 사라졌거나, 형식이 바뀌었거나, 다른 요청의 것이면 추측하지 않고 목록으로 알린다.
- **비교 화면:** 좌우 비교는 프로그램이 줄 단위 LCS로 직접 만든다. 바뀐 줄 안의 가운데 부분을 강조하고, 두 화면 스크롤을 연결하며, 가운데 막대로 크기를 조절한다.
- **적용:** 적용을 누를 때만 반영한다. 요청 사이에 공개 내용이 바뀌었으면 덮어쓰지 않는다.

## 6. 백업 (BACKUP_*)

- **주 로컬 백업:** 기존 restic 방식을 그대로 쓴다. `BackupPrivate`(기본 켬)로 private(암호문)을 포함할지 고른다. 범위 태그(`scope-full`/`scope-noprivate`)를 붙이고 보존은 태그별로 계산하므로, 옵션을 바꿔도 이전 범위의 복구시점을 지우지 않는다. 복구시점 목록에 범위를 표시한다.
- **수동 백업파일:** "백업파일 만들기"를 누를 때만 만든다. 형식은 `.wobak`이며 구조는 아래와 같다.
  - `WOBK` 머리말, PBKDF2 소금, 1MiB 단위 AES-256-GCM 조각으로 되어 있다.
  - 각 조각은 순번과 마지막 표시를 인증해 잘림·순서 바꿈을 탐지한다.
  - 안쪽은 ZIP이고 파일 목록과 해시를 담은 `업무정리_백업정보.json`이 들어 있다.
  - 암호는 사용자가 입력하는 업무정리 암호다. 만들 때의 암호로 잠기므로, 나중에 암호를 바꿔도 이미 만든 파일은 만들 당시의 암호가 필요하다.
- **복구 흐름(2026-10-31 사용자 확인):** 업무정리 암호 입력 → 앱이 복구정보에 잠긴 백업 비밀키(restic 내부 암호)를 풂 → 그 비밀키로 백업 저장소를 열어 복원. 업무정리 암호로 백업 데이터를 직접 푸는 것이 아니다. 복원된 private은 같은 업무정리 암호로 자료 키를 꺼내 연다.
- **외장디스크 사본:** "복구정보 저장"과 "암호 변경" 때 백업 위치의 `업무정리_백업복구정보.txt`(저장소 폴더 옆)에도 같은 복구정보를 쓴다. 그래서 다른 PC에서는 외장디스크와 업무정리 암호만으로 복원할 수 있다. 사용자 암호를 저장하지 않으므로 자동 백업은 이 사본을 만들 수 없다. 사본이 없으면 백업 결과에 다시 저장하라는 안내를 붙인다.
- **복구정보 파일:** restic 내부 암호를 업무정리 암호로 감싼 텍스트 파일(`업무정리 백업 복구정보 v2`)이다. 파일만으로는 복원할 수 없고, 다른 PC에서는 "복구정보 파일 + 업무정리 암호"로 복원한다. 암호 변경 뒤에는 새 암호로 다시 저장하도록 안내한다. 이전 판(암호 평문) 복구정보도 가져올 수 있다.
- **백업파일에서 빼는 것:** private 폴더와 `.private` 파일 전부, 이전본(`.previous`)·임시본(`.tmp`·`.partial`), `.업무정리` 안의 색인·키·잠금·저널·private 보관소 정보, 업무폴더의 이전 단일기록 평문(`업무기록*.txt`).
- **백업파일에 넣는 것:** 설정·업무목록·기본양식·지난제출물.
- **백업파일 만들기 순서:**
  1. 임시 ZIP을 만든다.
  2. 파일 구성과 해시가 그대로인지 다시 확인한다.
  3. `.partial` 이름으로 암호화한다.
  4. 다시 해독해 목록을 확인한다.
  5. 확인되면 완성 이름으로 바꾼다. 실패하면 불완전한 파일을 남기지 않는다.
- **위치 제한:** 업무 루트 안이나 restic 저장소 안에는 만들지 않는다.
- **복원:** 빈 별도 폴더로만 풀고 해시를 확인한다. 현재 업무 루트에 적용하지 않으므로 현재 private을 지우지 않는다.
- **하지 않는 것:** 업로드·로그인·동기화·자동 생성.

## 7. 이전 단일기록 (MIGRATION)

- 공개기록 없이 `업무기록.txt`만 있는 업무는 "미분류"로 표시한다. 화면 표시와 로컬 검색에는 쓰지만 AI 전송에는 쓰지 않는다.
- 상세창에서 기존 기록을 읽기 전용으로 보며, 사용자가 공개/private에 직접 나눠 저장한다. 앱이 자동으로 분류하지 않는다.
- 공개를 저장한 뒤 "기존 기록을 private 보관본으로 옮기기"를 누르면 `private\기존단일기록.private`에 암호문으로 보관한다. 다시 해독해 같음을 확인한 뒤에만 평문을 지운다.
- 평문이 남아 있는 동안에는 외부 폴더 AI 작업을 시작하지 않는다.
- 기록 양식 `업무기록.txt`를 고르면 그 내용은 private 상세에 넣는다. 공개용 기록 양식은 `공개기록.txt`라는 이름으로 등록한다.
